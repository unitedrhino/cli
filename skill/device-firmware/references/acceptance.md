# Watcher 实机验收

## 平台准备

1. 运行 `ur check --json` 复用当前认证，不为验收重置正常 profile。
2. 用 `ur-product` 核对目标产品已开启密钥认证和动态注册，并查看真实物模型标识符。
3. ProductID、设备名、环境和串口都从当前项目确认，不使用其他任务的固定值。
4. 对列表、控制或上传命令的 CLI 参数有疑问时先看 `--help`。
   如果当前 CLI 版本不能表达平台契约，使用同一认证上下文调用已确认的
   `ur api` 端点，不猜路径。

## 端到端顺序

1. 仅清理本次测试设备的云端绑定和设备侧 `nvs`，保留 `nvsfactory`。
2. 用 BlueZ 扫描 FFF0，发现 FFE1/FFE3，完成 WiFi、动态注册、Token 绑定和重启后自动上线。
3. 验证首连 `reportInfo` 以及至少三个周期的所有要求属性。
4. 下发可写属性和行为，核对 camelCase 回执、设备状态和后续上报一致。
5. 注入无效 DeviceSecret，确认连续三次明确鉴权失败后恢复注册；
   另行测试普通断网不清密钥。
6. 创建单设备、定向、主动推送的全量 OTA 任务，核对进度、MD5、备用分区、目标版本和平台任务成功。
7. 云端解绑后确认设备清凭据并重新广播，再次 BLE 配网后恢复上线。
8. 完成真实断电并观察不少于 15 分钟。若期间收到外部 `Reboot`，从 MQTT 重连时重新计时。

## 生命周期限制

部分平台版本的“解绑”只清项目归属，不恢复动态注册的未激活状态；
设备侧已清 DeviceSecret 时可能收到 `100019 设备已注册`。优先使用
平台正式生命周期接口恢复待注册态；没有公开入口时停止并说明限制。
只有隔离测试环境且已备份精确记录时才能做单设备状态复位，不得批量修改或套用到生产。

## 收尾

- 停止本任务的串口、BLE 和辅助进程。
- 删除明文 WiFi、绑定 Token、测试 NVS 副本和临时脚本。
- 受限目录中的整片 Flash、出厂分区备份和 OTA 验收记录按任务要求保留。
