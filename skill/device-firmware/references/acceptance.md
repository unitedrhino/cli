# 设备固件端到端实机验收

验收对象必须固定为唯一环境、ProductID、DeviceName、硬件、串口和固件版本。测试平台
写操作、NVS 清理、烧录、解绑和 OTA 都只能作用于已授权目标。

## 验收前门禁

- `ur check --json` 已确认环境、企业、应用和管理员权限。
- 产品、物模型、注册/绑定策略已回读；所有 identifier 来自真实模型。
- 首刷备份大小和 SHA-256 已核验，出厂分区不会被写入。
- 旧版和目标版均可复现构建；目标应用镜像小于 OTA 分区。
- 固件、构建日志和 Git diff 未发现明文凭据。
- 串口、BLE 和网络日志的时间同步，能够用 Token 关联。

## 核心验收顺序

1. 清理仅限目标测试设备的云端状态和业务 NVS；保留出厂身份。
2. 使用产品声明的 BLE/SoftAP 流程完成 WiFi、动态注册和可选 Token 绑定。
3. 确认 DeviceSecret 持久化、设备在线、首连 `reportInfo` 成功。
4. 观察至少三个正常上报周期，逐个核对必需属性的类型、范围和值。
5. 下发每个可写属性的代表值，核对真实硬件状态、`controlReply code=200` 和后续上报。
6. 调用每个关键行为，核对 `actionReply`、输出模型、幂等和物理效果。
7. 触发一次软件重启，确认只重启一次并自动重连、重订阅和上报。
8. 注入无效 DeviceSecret，确认只在连续明确鉴权失败后重新注册且 WiFi 保留。
9. 单独制造普通断网，确认不会清 DeviceSecret，网络恢复后自动上线。
10. 从可升级旧版执行单设备全量 OTA，验证进度、MD5、备用分区、目标版本、
    `reportInfoReply` 确认和平台任务成功。
11. 验证一个失败 OTA 场景和确认前异常重启，确保拒绝或 rollback。
12. 云端解绑后验证设备按产品策略清身份并重新进入配网，再次接入恢复在线。
13. 现场完成一次真实断电，验证 WiFi、DeviceSecret、版本和启动分区持久化。
14. 连续观察不少于 15 分钟；无意外复位、属性持续上报、平台在线稳定。

如果稳定观察期间收到外部重启行为，从 MQTT 重新连通时重新计算观察窗口。

## 三方证据

每个关键步骤都至少保留：

| 视角 | 证据 |
|---|---|
| 设备 | reset reason、版本、阶段日志、物理状态、脱敏 Token |
| 网络 | BLE/SoftAP 交互、MQTT Topic、请求/回复 Token、OTA HTTP/MD5 |
| 平台 | 设备在线、Hub/属性/行为日志、reportInfo 版本、OTA 任务结果 |

CLI/API 返回 `code=200` 只证明请求受理；必须同时验证设备物理状态和后续上报。

## 生命周期限制

部分平台版本的“解绑”只清项目归属，不恢复动态注册的未激活状态；设备侧清
DeviceSecret 后可能收到“设备已注册”。优先使用平台正式生命周期接口恢复待注册态。
没有公开入口时停止并说明限制；仅在隔离测试环境、已备份精确记录且获得明确授权时，
才能做单设备状态复位，禁止批量修改或直接套用到生产。

## 交付和清理

- 设备最终处于目标版本在线状态，平台版本和 OTA 任务一致。
- 记录产品/设备/固件/任务 ID、代码 SHA、构建摘要、验收时间和未覆盖项。
- 停止本任务串口、BLE、代理和辅助进程。
- 删除明文 WiFi、绑定 Token、临时 NVS 副本、签名 URL 和临时脚本。
- 受限目录中的整片 Flash、出厂分区备份和 OTA 证据按任务要求保留。
- 需要现场人工断电、审核或发布的步骤明确标记，不能把“待人工”写成“已通过”。
