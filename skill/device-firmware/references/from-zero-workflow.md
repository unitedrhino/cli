# 设备从零接入工作流

本流程用于 AI 同时具备固件代码、目标设备和联犀平台操作权限的任务。
如果用户只要求设计或代码，不执行平台写入、烧录和设备控制。

## 必要输入

开始前从任务上下文或只读检查取得：

- 目标环境及 MQTT 地址；
- 硬件型号、芯片、Flash 大小、串口和供电方式；
- 固件仓库、构建入口、当前版本和目标版本；
- 是否复用产品，目标物模型、设备名和配网方式；
- 静态三元组或动态注册、是否需要用户绑定；
- 首刷、清理测试 NVS、平台写操作和 OTA 发布的授权范围。

缺少产品/设备标识时先查询，不从列表中随意选择第一项。涉及多个合理目标且
无法从任务确认时停止询问；不要把一次接入扩展到同产品其他设备。

## 阶段 1：只读盘点

1. `ur check --json`，确认 base URL、应用、企业和角色。
2. 查询同名产品、产品详情、物模型和目标设备，判断复用还是创建。
3. 读取分区表、构建配置、网络管理器、身份存储、MQTT 和 OTA 现有实现。
4. 记录设备当前版本、MAC/序列号、Flash 大小、启动分区和 reset reason。

完成判据：平台目标唯一；硬件和串口唯一；明确哪些资源将创建或修改。

## 阶段 2：平台骨架

1. 创建或核对产品：`urMqtt`、设备类型、网络类型、认证、动态注册和绑定级别。
2. 生成并校验物模型；导入后回读，保存真实 identifier、类型、范围和读写模式。
3. 静态模式创建设备；动态模式确认产品开启对应注册策略。
4. 需要用户绑定时创建绑定 Token，并保存到受限临时文件，不写普通日志。

执行命令和最小请求见 [平台初始化](platform-bootstrap.md)。

完成判据：产品启用；物模型回读一致；设备身份策略明确；没有把 ProductSecret
或 DeviceSecret 写入仓库。

## 阶段 3：固件最小在线闭环

先实现最小闭环，再加业务功能：

```text
安全存储 → 配网 → 获得 IP → 校时
→ 动态注册（仅无 DeviceSecret）→ MQTT 鉴权
→ 订阅下行 → reportInfo → 属性上报
```

必须先让以下信息可观察：启动原因、固件版本、网络状态、注册阶段、MQTT 状态、
订阅结果和消息 Token。日志只打印状态和脱敏摘要。

完成判据：设备重启后无需人工再次写入凭据即可上线；平台收到匹配版本的
`reportInfo` 和至少一组合法属性。

## 阶段 4：完整双向通信

1. 周期和变化触发属性上报；需要时实现事件上报。
2. 属性控制先校验，再执行硬件动作，再回复，最后重新上报实际值。
3. 行为调用按 `actionID` 路由，耗时动作放 worker，并返回物模型声明的结果。
4. `msgToken` 原样关联请求与回复；重复 Token 不重复执行不可逆动作。
5. MQTT 断线后重订阅；普通网络失败不清 DeviceSecret。

完成判据：平台控制返回成功、物理状态改变、后续上报一致；行为结果可查询；
断网恢复后不需要重新配网。

## 阶段 5：首刷与分层验证

1. 首刷前备份整片 Flash 和出厂分区并校验大小、SHA-256。
2. 使用构建产物的分区级 `flash_args`，不写 merged binary 覆盖身份分区。
3. 按串口 → WiFi → 注册 → MQTT → 平台 Hub 日志 → 物模型日志的顺序定位问题。
4. 验证首次上线、三轮周期上报、属性控制、行为和一次软件重启。

完成判据：每条业务消息都能由同一 Token 在设备日志和平台日志中关联。

## 阶段 6：OTA 闭环

1. 先刷可升级的旧版本；目标版本必须不同。
2. 构建应用分区单文件，核对大小、版本、MD5 和 ESP/目标平台镜像。
3. 上传文件，创建固件记录，再创建单设备静态定向任务。
4. 设备 worker 下载、校验、写备用分区、上报进度并重启。
5. 新镜像上报 `reportInfo`；收到匹配回复后确认镜像。
6. 主动测试损坏摘要、错误版本或中断下载，确认拒绝或 rollback。

完成判据：设备、平台设备详情和 OTA 任务三处版本一致，任务最终成功。

## 阶段 7：恢复与交付

1. 注入无效 DeviceSecret，仅在连续明确鉴权失败后重新动态注册；WiFi 保留。
2. 普通断网测试不得清密钥。
3. 云端解绑后验证设备按产品策略清身份并重新进入配网/绑定。
4. 真实断电后确认 WiFi、DeviceSecret、版本和启动分区持久化。
5. 连续观察不少于 15 分钟；外部 Reboot 会重置观察窗口。
6. 删除明文临时凭据，停止任务进程；保留受控 Flash 备份和验收记录。

完成判据：设备最终处于目标版本在线状态，无意外复位，属性持续上报；交付记录
明确代码、平台资源、验证、OTA、清理和仍需人工完成的事项。
