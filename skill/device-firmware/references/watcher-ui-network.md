# Watcher 圆屏 UI 与保留绑定换网

适用于 TASK-143 接口及实现；发布前先确认目标固件和小程序已包含该能力。
开发分支测试通过不等于设备已经升级，未部署时不得向用户承诺可以换网。
环境、设备、串口和受控备份位置从当前任务与部署环境说明读取，不沿用历史设备。

## 界面与输入所有权

- Watcher 是 412×412 圆屏，关键文本与焦点限制在中央安全区域；矩形截图不证明圆屏可读。
- 主页/对话单击开始或打断后监听，双击拍照，长按 2 秒进入菜单并关闭语音。
  菜单中滚轮仅移动焦点，单击确认，长按返回；不得再触发音量快捷键或拍照。
- 恢复出厂放在电源确认页，默认取消。USB 供电显示重启，电池供电显示关机；
  不保留持续长按自动擦除 NVS 的暗路径。
- 网络、相机、音频任务只投递事件，LVGL 显示任务操作对象。保持页面控制器唯一，
  状态栏可复用 top layer，不为每页重建驱动。重复终态不得抢焦点或重开已退出页面。
- 测试固件可用 `ur_hw_test press / double-press / long-press / next / previous` 注入输入；
  必须走物理按键共用的板级分发，禁止直接调用聊天函数冒充按键 E2E。
  ACK 仅表示排队；长按注入不验证触点持续 2 秒，屏幕实际显示仍需另验。
- 活动对话、相机 worker 和换网禁止息屏；唤醒输入不透传业务动作。菜单空闲 30 秒
  返回主页，但正在配网不能因此退出。长字幕分区可滚动；预览不被普通状态消息清除。
- 网络结果页显示非敏感错误原因；存储恢复失败只能重启重试，不能绕过恢复继续联网。
- 动态字体替换必须覆盖未激活页面和 top layer；LVGL 样式只保存字体裸指针，旧字体
  所有者释放前同步更新全部页面。只更新当前屏会在稍后打开菜单时触发悬空指针崩溃。

## 本地换网事务与项目管理员授权

换网保留正式 Wi-Fi 列表、DeviceSecret、所属项目和绑定；候选配置独立持久化。
BLE 配网独立启动，不与正常 WifiManager 并行初始化。OTA/相机忙时拒绝入口，
进入换网先关闭语音，设备在线和离线都可从本地菜单开启。新版小程序不依赖物模型行为。
管理员按真实项目拥有者或项目级 AuthAdmin 判断，不是扫码操作者、普通控制权或全局管理员标志。
设备可以离线，手机必须联网取得当次许可；手机也离线时拒绝，不提供未鉴权降级。

| 合同 | 内容 |
|---|---|
| `configureNetwork` | 可选在线唤起行为，输入 `requestId` 为 16 位十六进制字符串，输出布尔 `Result`；本地菜单不依赖该行为 |
| 本地闭环 | 不新增状态属性、不等 MQTT 回执；设备域授权接口只负责权限和许可，已有 `networkConfigStatus` 不作为前提，也不自动删除 |
| 阶段 | 0 空闲、1 已准备、2 BLE 等待、3 候选连接、6 提交、7 已保存、8 失败、9 待物理确认；4/5 为旧流程保留值 |
| 错误 | 0 无、1 重启中断、2 超时、3 取消、4 鉴权（旧流程保留）、5 网络、6 存储 |

BLE 等待最多 180 秒；取得 IP 后还须确认实际关联 SSID 与候选一致，
保存提交意图、写入并回读正式列表、持久化成功终态，然后才发送标准联网成功通知。
GATT 写完成、取得 IP 或阶段受理均不能直接显示成功。云端不可达不撤销已保存的新网络，
应单独显示云端离线。换网不清密钥、不动态注册；提交前取消、超时、异常启动恢复旧配置。
正式配置写入中断需先完成恢复并回读，恢复不确定时停止普通联网，不能丢失旧网络。

仅使用可选在线入口时，通过既有 API 查询行为、仅创建缺项、回读确认；冲突停止，不覆盖其他能力。
在包含 TASK-143 工具的 SaaS 仓库根目录：

```bash
python3 shell/converge-watcher-network.py --check \
  --expected-base-url '<当前环境地址>' --expected-tenant-code '<当前组织编码>'
# 目标及环境门禁通过、写操作获授权后，才将 --check 改为 --apply。
python3 shell/test-converge-watcher-network.py
```

工具当前限定 Product 8；其他产品不能照抄执行，应先核验并调整目标合同与测试。
`--check` 返回 1 表示缺项，2 表示检查失败；`--apply` 部分失败可幂等重跑，但不得忽略合同冲突。

## BLE 与小程序边界

沿用 FFF0/FFE1/FFE3。当前开发 E5 v3 重组后为 31 字节：`e5 00 1c 03 01 stage error`
后接 8 字节请求 ID、16 字节窗口随机挑战。仍按原通知协议分片；旧 v1/v2 换网必须升级，
不能回退到首次绑定。v3 尚需配套发布和真实验收，不把此前 v2 真机结果当作 v3 验收。
`changeNetwork` 必须在申请绑定 Token 之前分流。手机写入 E5 是读取日志、设备以 E4 回复；
设备通知 E5 才是换网能力，不能混淆方向。

写凭据前调用设备域 `POST /api/v1/things/device/network/grant`，以 ProductID/DeviceName 查询
真实项目权限。`checkOnly=true` 只预检查；正式签发传 `nonce`、`credentialDigest`，不传密码。
摘要是 `SHA256("ur-wifi-v1\n" + hex(UTF8(ssid)) + "\n" + hex(UTF8(password)))` 的小写 hex。
签名原文是 `"ur-network-v1\n" + productID + "\n" + deviceName + "\n" + nonce + "\n" + digest`，
使用 DeviceSecret 原始 UTF-8 文本作 HMAC-SHA256 key；手机只能得到签名，不能得到密钥。
签名解码为 32 字节，经两包 `E6 00 11 part[0/1] signature[16]` 发送；等待各自
`E6 00 02 part result`、result=0 后才下发候选。回执只代表分片受理；实际验签在 worker，
拒绝时不写候选 NVS，且消费许可。挑战仅本次最长 180 秒窗口有效，重启、取消或退出后无效。
保留普通绑定协议；E2 密码、E4 Token、E6 许可（包括分片）不能记录到日志或 Sentry。

WiFi 配网广播的版本是完整字节 `02`，不能套用标准蓝牙模式的高四位版本编码。
微信厂商数据包含两字节 Company ID；BlueZ 的 ManufacturerData 已以 Company ID 为键，
对应值是从版本开始的 17 字节正文。协议测试应回放真实结构，不能只锁定源码正则。

GATT 回调栈可能只有数 KB；候选事务及 NVS 校验会叠加多个网络快照，不能直接在回调执行。
回调只校验并复制到有界信箱，由已有换网 worker 持久化和设置临时 STA，完成后才通知受理。
测试须断言回调零持久化、提前 E3 拒绝、队列满、保存/驱动失败及密码副本清零；
主机测试没有 MCU 栈限制，仍须用同步串口捕获真实 E2 写入，区分 ATT 错误与 BTC_TASK 栈溢出。

- 同产品可能有多台设备；广播只用于筛选，写 Wi-Fi 前必须通过 GATT 核对所选 DeviceName。
  自动发现仅在明确的身份不匹配时断开并检查下一候选；连接、能力或断开失败立即停止。
  用户明确选择的错误设备不能自动换成另一台，错误设备不得收到密码。
- 候选指令前后核对连接代次、会话代次、请求 ID；取消后的迟到通知/HTTP 回复不能推进新会话。
- Wi-Fi 页面卸载后不得由异步初始化重新订阅、挂监听或写状态；向进度页主动交接则保留会话。
- 提示 2.4GHz 并保留手动输入；不要使用“长按 5 秒、灯快闪”的旧 Watcher 文案。
- 小程序须核对当前设备、连接代次、有效请求，以及标准 E2 的连接成功和目标 SSID；
  E2 本身没有请求 ID，不能只凭一条迟到成功包完成流程。
- 保存后保留 30 秒 BLE 结果窗口。等待结果异常时最多重连原设备一次，
  仅在同一请求已提交后发送 E3 只读查询，不重发模式/密码/Token；页面内同请求重试同样只读。
  窗口结束、结果未提交或重查失败保持“未确认”，不能凭断开或历史在线宣称成功。
  整个换网路径不得调用绑定/解绑、创建 Token 或修改项目归属接口。

## 最近网络与构建适配

- 保留最近成功使用的 10 个 SSID；同名更新，不保留同名不同密码的多条记录。
- 正常取得 IP 才更新独立排序 blob，只存 SSID；重复连接首项不写 Flash。
  候选提交按最近顺序保留旧网络，第十一项淘汰最久未成功使用项；失败不淘汰旧网。
- 排序损坏不能隐藏有效凭据或触发解绑，回退原槽位顺序；提交中断必须恢复旧快照及顺序。
- 连接正常时不主动切网；断开后扫描已保存网络，最近成功网络优先，同 SSID 保留信号排序。
- 多网络必须完整扫描后排序；旧缓存信道可见旧 AP 时，驱动可能不再全扫，导致新热点永远不进入排序。
  回归应执行真实生成的扫描函数，覆盖跨信道新热点与单网络快速扫描；不要仅测试排序数组。
  BLE 提交后还须核对重启后的实际 SSID/IP，再确认 MQTT 恢复，禁止仅凭平台在线判换网通过。
  可复测命令：`python3 firmware/watcher/scripts/run_ur_network_e2e.py --product-id <产品ID> --device-name <设备名> --mac <蓝牙MAC> --verify-boot-log <本次串口日志> --expected-ssid <新网络名>`。
  该模式只读日志，不操作蓝牙；要求最近启动中的网络、IP、指定设备 MQTT 和属性回执齐全。
  它不替代 BLE 请求关联、密钥/绑定回读或手机验收。
  已保存网络暂不可用时持续重试，不因启动 60 秒超时自动停止 STA 并开启热点。
- Watcher 构建在 build 内生成扫描源副本，适配多网络全信道扫描与最近网络排序，继续使用原驱动连接和重试；
  不手改 managed_components。生成器锚点漂移必须阻断构建并审查，不能静默退回信号优先。

## 可复测验收

在直连 Linux 上使用仓库 `firmware/watcher/scripts/run_ur_network_e2e.py`：

```bash
python3 firmware/watcher/scripts/run_ur_network_e2e.py \
  --product-id '<产品ID>' --device-name '<设备名>' --mac '<广播MAC>'
```

先从设备菜单开启换网窗口。默认只读身份和能力；只有明确授权写候选时加
`--provision-stdin`，通过受控 stdin 输入 `ssid/password/nonce/signature` JSON，不把密码写入参数。
先只读取得本次 nonce，再以管理员登录身份调用授权 API，随后在同一窗口写入；
脚本不读取设备密钥，许可缺失或窗口变化即停止。不能复用旧脚本绕过权限验收。
需要 Linux 系统 dbus/gi 和 BlueZ；失败不自动重发凭据，断开或脚本观察超时不是成功。
脚本回放单测为 `test_network_e2e_runner.py`，不替代真实 GATT 与手机验收。

检查热点实际广播频段，不只看设置页的“任何可用频率”。Linux 先执行
`nmcli device wifi rescan ssid '<目标SSID>'`，确认无权限/扫描错误并等待扫描完成后，
再查看 `nmcli -f SSID,FREQ device wifi list --rescan no`。SSH 会话可能无扫描权限；
`list --rescan yes` 即使退出码为 0 也可能只返回缓存。无法确认新扫描时应标记未知，
不能据缓存未列出热点要求现场反复修改或阻止已授权的真实设备配网测试。
Watcher 需要 2.4GHz；只有新扫描证实同名热点仅在 5GHz 时才据此要求调整。
其他设备成功连接不证明 Watcher 兼容该频段，设备连接超时也不能直接推断密码错误。
错误密码用例可对已有 SSID 写入明确错误的候选密码，再等待设备完整超时窗口；
必须同时核验重启后原网络恢复、MQTT 在线和身份/绑定未变。脚本返回断开只表示
未取得成功确认，不能单独证明恢复成功。

先记录固件 SHA/版本、手机系统、小程序构建配置、物模型合同及现有绑定；密钥比较仅在
受控工具内执行，不把明文或完整认证响应写日志。默认配置或占位密钥构建禁止刷写/上传。

| 层次 | 必须覆盖与判据 |
|---|---|
| 生产核心单元 | 候选隔离、原密钥保留、37 个提交失败位置、最近顺序/十槽淘汰/首项零写、重复请求、超时、OTA/相机互斥；关键逻辑连续 10 次 |
| UI 主机测试 | 菜单焦点/返回、默认取消、唤醒吞键、单/双/长按互斥、长字幕、预览/表情切换、21 情绪及未知回退；不得称为像素或按键硬件验收 |
| 双端小程序 | 首次绑定/换网分流、零绑定接口调用、同产品错误设备在前、手选错误、权限/蓝牙中断、迟到结果、页面卸载与主动交接 |
| 真实 BlueZ | 真机 GATT 身份、能力/候选帧、断开与重连；只能证明 Linux 协议链路，不能替代微信手机权限和蓝牙兼容性 |
| 网络硬件 | A→B→A、关闭旧网络、错误密码、DHCP 失败、平台不可达、换网中真实断电；候选失败回旧网，已可靠保存则保留新网，云端离线单独展示，绑定与密钥不变 |
| Android / iOS | 两个平台各用测试小程序完整换网，等待当前请求成功，核对名称、项目、绑定；保留截图/时间关联，不发布正式版 |
| 整机 | 多轮语音/两种打断、完整字幕、真相机预览识图、五类代表情绪、USB/电池电源菜单、OTA、15 分钟稳定性；音频无卡顿、无持续堆下降 |

主机用例入口位于 `firmware/watcher/scripts/tests/`，重点 `test_ur_network_*`、
`test_network_grant.py`（实际固件验签与 Go/TS 固定向量、许可单次消费）、
`test_watcher_wifi_retry.py`、`test_wifi_scan_generation.py`、`test_watcher_ui_runtime.py`、
`test_watcher_display_mailbox.py` 和 `test_watcher_page_manager.py`；
双端测试位于各应用 `scripts/*.test.cjs`，通过各应用 `test:contract` 入口运行。
网络授权服务用 `networkgrant` 域测试及 `things/device/network` logic RPC mock 测试；
覆盖项目拥有者/管理员允许，普通读写/区域管理员/跨组织/同名其他产品拒绝。小程序补充
授权缺失、失败、迟到和错误签名零凭据写入；`network-grant-runtime.test.cjs` 验证 UTF-8 摘要。

失败证据按层归属：无 E5 查固件能力/BLE窗口；E5 正常但身份拒绝查目标与连接代次；
取得 IP 但不提交查实际关联 SSID、NVS 保存/回读和事务终态；设备已保存但手机等待查 BLE
分片重组、当前请求、连接代次和结果窗口，不查云端状态属性来替代 BLE 结果；
模拟全通过但真机卡顿查显示线程、音频资源及功耗。保留明确未测项，不能把被阻挡的 E2E 标通过。
