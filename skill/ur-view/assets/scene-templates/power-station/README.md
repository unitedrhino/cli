# 配电站三维场景模板

可独立复制的 Three.js r128 配电站源码。保留灰色金属柜体、门缝与五金、玻璃、环氧地面、室内柔光、预烘焙反射、巡航和可拾取仪表。布局包括两列低压柜、128 个仪表锚点、高压柜、两台变压器及母联结构；数量仅用于展示布局，不表示任何现场台账或已核实电气连接。

运行资源全部本地提供，无外部模型、HDR 或渲染框架。没有样例读数、随机数据提供器或连接失败回退。独立打开时显示未绑定，模型仍可旋转、聚焦和巡航。

## 启动与打包

复制整个本目录到自己的工作目录后执行：

```bash
python3 -m http.server 8768 --bind 127.0.0.1
python3 package.py
python3 package.py --output .temp/power-station.zip --preview .temp/offline.html
node provider.test.cjs
```

浏览器打开本地服务端口即可查看。打包仅包含 `index.html`、`css/`、`js/`、`libs/` 和 `LICENSE.txt`；README、测试、临时文件及截图不会进入 ZIP。默认输出到 `.temp/power-station.zip`，构建超过 2 MB 会失败。单文件 HTML 也不含任何凭证或演示数据。

运行可选浏览器验收需要外部开发环境安装 Playwright，不能将它复制进运行资源：

```bash
node verify.cjs
```

测试自行创建并关闭本地服务和浏览器，产物写 `.temp/verification/`。`bake-environment.cjs` 可重新生成无外部素材的室内反射图；它会更新 `js/environment.js`，只有修改材质反射设计时才需运行。

## 配置与绑定

`js/data.js` 的 `LV_SECTIONS`、`HV_CABINETS`、`TRANSFORMERS`、`BUS_CABINET` 定义可替换结构与本地名称。不要把现场设备身份写入模板。本地仪表编号用于稳定锚点 `meter/<本地编号>`，例如 `meter/A-IN-M`。已发布场景调整编号前应迁移宿主绑定。

`STATION_DATA` 定义以下接入参数：

- `fields`：每个显示字段的 `identifier` 初始为空。核验物模型后填准确标识符，查询和推送均严格匹配，不猜别名。全部标识符为空时不发送设备 API 请求，并显示“物模型未配置”。`multiplier` 必须为正数，将源单位转换为模板固定显示单位：电压 V、电流 A、功率 kW、无功 kvar、电量 kWh。例如源单位 W 到 kW 的倍率是 `0.001`。`unit` 记录这个目标单位，不应单独修改它来替代换算。接入多产品时须确认这些字段合同一致，不一致应分别制作对应配置的场景。
- `on`：通过 `trueValue`、`falseValue` 显式映射开关原始值；不认识的值显示空，不能因没有状态就显示合闸。
- `staleMs`：默认 75 分钟，应按核实的上报周期调整；`pollMs` 默认一分钟；`historyStepMs` 默认 30 分钟，均使用正毫秒数。
- `summary`：默认 `verified: false`、成员为空，因此显示“未配置汇总”。只有核实进线与下级关系后，才填 `meterIds` 并启用。仅进线结构允许参与；混入馈电、成员无绑定或任一字段缺失时不汇总。相同产品与设备组合即使绑到多个锚点也仅计一次，负功率不会截断。

产品与设备由大屏 EmbedPage 的锚点绑定配置提供，不硬编码在页面。绑定记录包含 `path`、`productID`、`deviceName`；缺产品身份或同一锚点绑定多个不同设备的歧义记录不采用。只有已绑定唯一设备会发起查询。宿主 SDK 负责凭证、授权与项目属性订阅，页面包和日志不持有令牌。

## 数据与交互行为

初值和增量经 `ur-scene` SDK 进入；快照始终带产品和设备组合，单次最多三路查询。经核实的进线成员优先，然后读取其他已绑定设备快照；不预取全产品或全仪表历史。重复握手保留缓存；绑定改变清理旧映射、状态及在途结果，旧设备推送不能回写新绑定。

字段各自保留上报时间戳，旧时间戳不会覆盖新值。零是有效读数，缺失、过期、未绑定、接口失败有独立状态；未配置开关状态显示 `--`。快照刷新和 SDK 增量均使用相同单位换算。顶部“有效读数”表示至少存在一个未过期已映射字段，不代表设备在线事件状态。

单击仪表查看详情，双击聚焦；左侧树可聚焦对应仪表，支持分区视角、旋转缩放、自动巡航与巡检。趋势只查询当前选中设备的指标，近一天按 30 分钟网格取该时刻之前且未过期的记录，缺口不连线、不补零；成功缓存一分钟，失败可点击重试。单次历史最多 20 页、每页 200 条；更高频采集应先在平台选择合理聚合或缩小采样密度。

## 上传与验收

1. 先完成物模型单位、周期和计量关系核验，保持未确认成员不参与汇总；名称与模型位置不代替电气边界证据。
2. 在宿主新建独立测试大屏和场景资产，上传生成 ZIP，用 EmbedPage 引用该资产，再配置锚点绑定；不要覆盖已有正式资产。
3. 检查唯一设备数量、零值、负值、无数据、过期、接口失败和恢复；对比快照、推送、历史单位与时间戳，确认没有进线与下级重复累计。
4. 验证总览、分区、仪表拾取与选择框、聚焦、巡航、详情和趋势切换；至少覆盖 1080p 和窄窗口，数据缓慢时模型仍先出现。
5. 记录无缓存与缓存加载、网络条件、设备、DPR、GPU 类型和旋转帧率。默认 DPR 上限 1.5、单主阴影光源及 2048 阴影贴图，目标主体 3 秒、细节 5 秒；软件 GPU 验收不能宣称硬件 30 FPS 达标。
6. 验收通过后按发布授权发布并回读；失败保持未发布。异常时取消新大屏发布，保留已有资产。

`provider.test.cjs` 覆盖绑定去重、不同产品同名设备、值与单位、零/负/缺失、旧时间戳、过期、严格汇总、缓存、历史断点、绑定在途隔离和错误恢复。`verify.cjs` 的夹具只存在测试进程中，不会随 ZIP 分发。
